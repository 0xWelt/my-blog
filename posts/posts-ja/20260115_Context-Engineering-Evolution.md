> 著者：0xWelt、kimi-k2-thinking-turbo

AGIは決して特定の企業の独自開発ではなく、エコシステムとインテリジェンスの双方向の旅です。この旅の中で、「Context」（コンテキスト）は技術的な概念から、コミュニティ全体が共同で書き上げる進化論へと進化しています。それはモデルが世界を理解する窓であると同時に、エコシステムがインテリジェンスの境界を拡張する画布でもあります。

今日、私たちはまた一つの転換点に立っています。コミュニティが単純なPromptやツールではなく、構造化され、シーンに即したContextをAIに提供し始めたとき、AGIの進化の軌道は静かに書き換えられています。まずはこれまでの道のりを振り返り、Context管理戦略がいかにして今日に至ったかを見てみましょう。

## 第一章：呪文の時代——System PromptとUser Inputの素朴な探究

すべては2022年末、世界を震撼させたあの冬から始まりました。ChatGPTの初代システムは、単純な「System Prompt + User Input」の二項構造の上に構築されており、これが人間とコンピュータの相互作用の最も基本的なパターンを定義しました。コミュニティはすぐに、慎重に設計された"魔法の呪文"——那些冗長で精密なUser Prompt——によって、モデルが特定の領域で基礎能力を超える驚異的なパフォーマンスを発揮できることを発見しました。

典型的な例は、かつて一世を風靡した"Academic GPT"です：ユーザーは長大な指示を入力し、モデルに学術論文の推敲専門家としての役割を果たすよう求め、文法や論理から引用形式に至るまで数十もの細則を規定しました。これらのPromptは錬金術師の配方のように、コミュニティの間で口伝されました。

しかし、この方式の天井はすぐに現れました：

- **能力の境界が低い**：当時のモデルのInstruction Following（指示追従）能力は萌芽期にあり、複雑な指示はしばしば実行がずれました
- **移行性が低い**：Aモデルに最適化された"呪文"はBモデルではしばしば機能せず、新しいモデルごとにゼロからの探索が必要でした
- **体験の断絶**：ユーザーは大量のテンプレートを記憶して入力する必要があり、対話は本質的に煩雑でした

この段階の遺産はほぼ空白ですが、一つの重要な示唆を残しました：モデルには断片化されたテキストの呪文ではなく、より構造化された能力誘導が必要です。

## 第二章：ワークフローの進撃——Fixed Agent Workflowの工業化への試み

2023年、Dify.ai、扣子（Coze）、LlamaIndexなどのプラットフォームが台頭し、「固定ワークフロー」の新しいパラダイムをもたらしました。開発者は特定のシーンに対して、ビジュアルインターフェースでマルチターンAgentを構築し、ツール呼び出しチェーンを設計し、RAG外部知識ベースと組み合わせることで、LLMを真のAgent時代に導きました。

これは質的な飛躍でした：モデルは単発の対話から長期的なタスクへ、純粋なテキスト対話からツール呼び出しへと拡張しました。コミュニティはこれを基盤に、オープンソースの自動運用アシスタントからクローズドソースの業界知識ベースQ&Aシステムまで、無数のAgent製品を生み出しました。ワークフロー技術により、LLMはより長時間稼働し、より多くの相互作用能力を獲得しました。

しかし、その欠陥も同様に明らかでした：

- **ケースバイケースのカスタマイズ**：各機能には重厚なワークフロー全体が必要で、コーヒーを一杯飲むために注文システム一式を展開するようなものでした
- **移行コストが高い**：GPT-4向けに最適化されたワークフローは、Claude上では全く異なるパフォーマンスを示すことがありました
- **柔軟性の欠如**：一度プロセスが固定されると、現実世界の動的な変化に対応することが困難になりました

それにもかかわらず、この段階は貴重な認知資産を残しました：

- 複数回の相互作用は、単発のLLMの能力上限を超えることができます——"人工的であるほど知的である"という逆説がここに現れます
- Agent Workflowは消滅せず、進化しました。今日私たちはharness（フレームワーク）やscaffold（足場）で類似の概念を表現しますが、Agentにより大きな自律的意思決定空間を与えています

## 第三章：MCP革命——動的インテリジェンスのツールカーニバル

2024年末から2025年初頭にかけて、MCP（Model Control Protocol）標準とともに静かな革命が巻き起こりました。これは全く新しい概念ではありません——OpenAIは2023年6月にはすでにTool DeclarationとTool Callの仕様を定義していました——しかしMCPはツール実装のコストを本当に底値まで下げました。

コミュニティは爆発的に反応しました：GitHub操作からフードデリバリー注文、データベースクエリからスマートホーム制御まで、大量のデジタルワールドAPIがMCP形式に迅速に整合され、巨大なMCP市場が瞬く間に形成されました。一方、Claudeを代表とする基盤モデルは強力なマルチステップtoolcall能力を示し、ツールを自律的に反復呼び出して複雑なタスクを完了することができるようになりました。

Fixed Workflowの枷は壊されました：Agentは事前設定されたrigidなプロセスを必要とせず、目標に応じて動的に経路を計画できるようになりました。能力の境界と汎用性が同時に向上し、AGIは手の届くところにあるかのように思えました。

しかし、問題もすぐに浮かび上がりました：

- **疑似需要の氾濫**：MCPは本質的にAPIの形式ラッパーに過ぎず、既存のAPIシーンでは開発コストが極めて低く、"ユーザーより開発者が多い"という滑稽な事態を招きました
- **AGIの幻覚**：コミュニティは"十分なMCPを接続すればAGIが実現できる"という妄信に陥り、モデル自体の能力の天井を無視しました
- **Context汚染**：ツールdeclarationの平面的な乱用がコンテキスト災害を引き起こし、数百ものツール定義がウィンドウを占拠し、モデルのInstruction Following能力が深刻に損なわれました。この問題を緩和するため、主流のAgentフレームワークはツール数の制限を開始しました——Cursorエディタは上限を80個に設定した時期がありました

危機は知恵を生みます。この段階の経験は、その後の設計哲学を深く変えました：

- 統一された規格はコミュニティの洪荒の力を引き出すことができます——標準化はエコシステム繁栄の基石です
- Context管理は精緻化されなければなりません——"hide tool result"などの単純な戦略の出現は、より体系化されたContext退出メカニズムを予告しました

## 第四章：Skillsの台頭——Context管理の次元上昇戦争

MCPの平面的な露出が限界に達したとき、Skillsが生まれました。これは単純なツールの再編成ではなく、Context管理戦略の次元上昇です。

Skillsが優れているのはなぜか？それは三重の突破を実現しました：

- **階層化された露出**：平らなツールリストを木構造に編成し、必要に応じて展開することで、Context汚染を回避しつつ貴重なコンテキストウィンドウを節約します
- **能動的なContext**：モデルが情報を受動的に受け取るのではなく、いつ、どの層のContextを取得するかを自律的に決定します
- **SOPレベルの指示**："何ができるか"（MCPの"私はXXツールを持っています"）だけでなく、"どうやるか"——詳細な標準作業手順が内蔵されており、ツールにインテリジェントなパッチを適用するようなものです

より破壊的なことに、多くのSkillsは完全に自然言語で定義され、プログラミングを必要としません。これによりコミュニティ参加の障壁が大幅に下がり、プログラマーではなくビジネス専門家もエコシステムにContext資産を貢献できるようになりました。ある意味で、これは第二段階のAgent Workflowの復活と超越です——自然言語の柔軟性を用いて、ワークフローの構造的な利点を蘇らせたのです。

しかし、これは同時にモデルに新しい課題を提起します：

- **能動的なコンテキスト制御能力**：数十回のツール呼び出し後でも、最初に指示されたあるSkillの存在を覚えていることができるか？
- **長文脈記憶能力**：深い呼び出しチェーンの中で、高レベルのContextへの認識をどう維持するか？

経験はすでに明らかです：

- Contextは階層化され、能動的に露出されなければなりません
- コミュニティが共同構築するのはツールだけでなく、プロセス知識——SOP、ベストプラクティス、領域方法論です

## 進行中のトレンド：Context管理の精緻化された進化

上記の進化史から、私たちは3つの連続した主線を明確に見ることができます：

### 一、平らから階層へ：拡張性の勝利

受動的にすべてのContextを取得する時代は終わりつつあります。より精緻で、より経済的で、拡張性の高い階層化された露出が主流になっています。これはエンジニアリングの最適化だけでなく、認知パラダイムの転換です——Contextの取得は情報の爆撃ではなく、情報の採集でなければなりません。

### 二、モデルの自律性の継続的向上

Bitter Lesson（苦い教訓）はここでも力を発揮し続けています：基盤モデルのインテリジェンスが向上し、Instruction Following能力が継続的に突破するにつれ、開発者はより複雑な構造を定義でき、モデルはそれを理解して実行できます。Agent Workflowは"less structure"になりつつあります——コード定義が必要なrigidなプロセスから、自然言語で記述される柔軟なSkillsへと進化しています。構造が少なければ少ないほど、インテリジェンスは増します。

### 三、コミュニティ参加障壁の継続的低下

エコシステムの広さがインテリジェンスの高さを決めます。Contextへの貢献にプログラミング能力が不要になり、ビジネス専門家が自然言語で直接Skillsを定義できるようになると、コミュニティの創造性は完全に解放されます。この民主化プロセスは、基盤モデルの能力境界を急速に拡張しています。

## 次の章：事前定義からシーン固有へ

しかし、物語は終わっていません。新しいトレンドが芽生えており、Contextの供給方式を変革しようとしています。

### トレンド一：「事前定義」から「シーン提供」へ

これまでのContextはすべて事前定義されていました：開発者がMCPサーバーを書き、Skillsをパッケージ化し、ユーザーが手動で選択してロードします。未来のContextは、シーンが能動的に提供するようになります。

世界を想像してください：コーヒーショップの経営者はAppやミニプログラムを開発する必要はなく、「Contextインターフェース」を実装するだけで済みます——ユーザーのAgentがジオフェンスに入店したり、店内のQRコードをスキャンしたりすると、そのシーンのContextパッケージを自動的に受信します。このContextには以下が含まれます：

- メニューと推薦（人間向けのGUIではなく、Agent向けの構造化データ）
- 注文プロトコル（Skillに似た自然言語SOP）
- 支払いフロー
- 待ち時間モデル

人間向けのGUIを作ることから、Agent向けのContextプロトコルを作ることへ——これはデジタルワールドの相互作用パラダイムの根本的転換です。

### トレンド二：「入るだけ出ない」から「柔軟な退出」へ

現在のContext管理は基本的に一方向です：ロード、ロード、そして再ロード——ウィンドウが爆発するまで。未来に必要なのは、Pythonの`with`文のようなコンテキストマネージャーのようなものです：エントリも退出も定義します。

ユーザーがコーヒーショップのシーンを離れると、Agentは自動的に以下を行うべきです：

- 詳細な相互作用ログをアーカイブする（"ラテを一杯注文し、キャラメルをバニラに変更し、少アイス"）
- 活動中のContextからそのシーンのMCP/Skillsを削除する
- 濃縮された要約のみを保持する（"Blue Bottle Coffeeで35元消費"）

このContext退出メカニズムは、長期的な汚染を回避しつつ、正確な記憶を実現できるため、長期稼働するAgentシステムにとって必須の能力です。

## 一杯のコーヒーで未来を見る

単純な例で新旧の世界を結びつけます：

**旧パラダイム**：

コーヒーショップに入る → QRコードをスキャンする → ミニプログラム/H5ページにジャンプする → ユーザーが手動で注文・支払いを行う

**新パラダイム**：

コーヒーショップに入る → AgentがシーンContextを自動検出する → 能動的にユーザーに知らせる："Blue Bottle Coffeeのメニューを検出しました。紹介しましょうか？" → ユーザーが自然言語で："少アイスのアメリカーノ、豆種はエチオピア" → Agentが選択、カスタマイズ、注文、支払いを自律的に完了する → 待ち時間を予測してリマインダーを設定する → 離店後にContextを自動クリーンアップし、消費記録のみを保持する

ユーザーは純粋な意図表現に回帰し、すべての中間プロセスはシーン化されたContextの指導の下でAgentが自律的に完了します。

## 結語：Contextネイティブなインテリジェントエコシステムへ

呪文からワークフローへ、MCPからSkillsへ、そしてシーン固有のContextへ——私たちは明確な主線を見ています：Contextは、人間の入力の付属物から、エコシステムの共生インフラストラクチャーへと進化しています。

AGIの鍵は、あるクローズドソースモデルのパラメータ数ではなく、コミュニティがコンテキスト豊かで、動的で、シーン化されたデジタルワールドを構築できるかどうかにあります。すべてのコーヒーショップ、すべての図書館、すべての実験室がAIにネイティブなContextを提供するとき、インテリジェンスは真に"創発"します。

これは技術の進化だけでなく、協力パラダイムの革命でもあります。ユーザーより多い開発者から、開発者より多いシーン参加者へ、エコシステムの次の章は、すべてのデジタル空間の保守者によって共同で書かれます。

**Contextはもはやモデルが処理すべき問題ではなく、世界がインテリジェンスに提供する答えです。**
