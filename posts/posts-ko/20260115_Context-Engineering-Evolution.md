> 저자：0xWelt, kimi-k2-thinking-turbo

AGI는 결코 어느 한 회사의 폐쇄적인 창조물이 아니라, 생태계와 지능의 양방향 여정입니다. 이 여정에서 「Context」(맥락)은 기술 개념에서 전체 커뮤니티가 공동으로 집필하는 진화론으로 진화하고 있습니다. 이는 모델이 세상을 이해하는 창문이자, 생태계가 지능의 경계를 확장하는 캔버스입니다.

오늘, 우리는 또 하나의 전환점에 서 있습니다. 커뮤니티가 단순한 Prompt나 도구가 아닌, 구조화되고 장면화된 Context를 AI에 제공하기 시작할 때, AGI의 진화 궤적은 조용히 재편되고 있습니다. 먼저 지나온 길을 되돌아볼까 합니다. Context 관리 전략이 어떻게 오늘에 이르게 되었는지 살펴 보겠습니다.

## 제1장：주문의 시대——System Prompt와 User Input의 소박한 탐구

모든 것은 2022년 말, 전 세계를 들썩이게 한 그 겨울부터 시작되었습니다. ChatGPT 초대 시스템은 단순한 「System Prompt + User Input」의 이항 구조 위에 구축되었으며, 이는 인간-컴퓨터 상호작용의 가장 기본적인 패턴을 정의했습니다. 커뮤니티는 곧 정교하게 설계된 "마법의 주문"——그 길고 정밀한 User Prompt——을 통해 모델이 특정 분야에서 기초 능력을 뛰어넘는 놀라운 성과를 보일 수 있다는 것을 발견했습니다.

대표적인 사례는 한때 유행했던 "Academic GPT"입니다：사용자는 방대한 지시를 입력해야 했고, 모델에게 학술 논문 다듬기 전문가 역할을 맡기며, 문법과 논리부터 인용 형식까지 수십 가지의 세부 규칙을 규정했습니다. 이들 Prompt는 연금술사의 비법처럼 커뮤니티 내에서 구전되었습니다.

하지만 이러한 방식의 한계는 곧 드러났습니다：

- **능력 경계가 낮음**：당시 모델의 Instruction Following(지시 따르기) 능력은 아직 초기 단계였고, 복잡한 지시는 종종 엉뚱하게 실행되었습니다
- **이전성이 낮음**：A 모델에 최적화된 "주문"은 B 모델에서는 종종 실패했고, 새로운 모델마다 처음부터 다시 탐색해야 했습니다
- **경험이 단절됨**：사용자는 대량의 템플릿을 기억하고 입력해야 했으며, 상호작용은 본질적으로 번거로웠습니다

이 단계의 유산은 거의 공백이지만, 하나의 중요한 시사점을 남겼습니다：모델은 단편적인 텍스트 주문이 아닌, 더 구조화된 능력 유도가 필요합니다.

## 제2장：워크플로우의 진격——Fixed Agent Workflow의 산업화 시도

2023년, Dify.ai、扣子(Coze)、LlamaIndex 등의 플랫폼이 부상하며 「고정 워크플로우」라는 새로운 패러다임을 가져왔습니다. 개발자들은 특정 장면을 위해 시각적 인터페이스로 다중 턴 Agent를 구축하고, 도구 호출 체인을 설계하며, RAG 외부 지식 베이스와 결합하여 LLM을 진정한 Agent 시대로 이끌었습니다.

이는 질적인 도약이었습니다：모델은 단발 대화에서 장기적인 작업으로, 순수 텍스트 상호작용에서 도구 호출로 확장되었습니다. 커뮤니티는 이를 기반으로 오픈소스 자동 운용 어시스턴트부터 클로즈드소스 산업 지식 베이스 Q&A 시스템까지 무수한 Agent 제품을 만들었습니다. 워크플로우 기술은 LLM이 더 오래 실행되고 더 많은 상호작용 능력을 얻게 했습니다.

그러나 그 결함 역시 분명했습니다：

- **케이스 바이 케이스 맞춤화**：각 기능에는 무거운 워크플로우 전체가 필요했고, 커피 한 잔을 마시기 위해 주문 시스템 전체를 배포해야 했습니다
- **이전 비용이 높음**：GPT-4에 최적화된 워크플로우는 Claude에서는 전혀 다른 성능을 보일 수 있었습니다
- **유연성 부족**：한번 프로세스가 고정되면 현실 세계의 동적인 변화에 대응하기 어려워졌습니다

그럼에도 불구하고, 이 단계는 귀중한 인적 자산을 남겼습니다：

- 다중 상호작용은 단일 LLM의 능력 상한을 초월할 수 있습니다——"인공적일수록 지능적이다"라는 역설이 여기서 나타납니다
- Agent Workflow는 사라지지 않고 진화했습니다. 오늘날 우리는 harness(프레임워크)나 scaffold(비계)로 유사한 개념을 표현하지만, Agent에게 더 큰 자율적 의사결정 공간을 부여했습니다

## 제3장：MCP 혁명——동적 지능체의 도구 카니발

2024년 말에서 2025년 초, MCP(Model Control Protocol) 표준과 함께 조용한 혁명이 몰아쳤습니다. 이는 전혀 새로운 개념이 아닙니다——OpenAI는 이미 2023년 6월에 Tool Declaration과 Tool Call 사양을 정의했습니다——하지만 MCP는 도구 구현 비용을 정말로 바닥까지 낮췄습니다.

커뮤니티는 폭발적으로 반응했습니다：GitHub 조작부터 배달 주문, 데이터베이스 쿼리부터 스마트 홈 제어까지, 대량의 디지털 월드 API가 MCP 형식으로 신속하게 정렬되었고, 거대한 MCP 시장이 순식간에 형성되었습니다. 한편, Claude를 대표하는 기반 모델은 강력한 다단계 toolcall 능력을 보여주며, 도구를 자율적으로 반복 호출하여 복잡한 작업을 완료할 수 있게 되었습니다.

Fixed Workflow의 족쇄가 깨졌습니다：Agent는 사전 설정된 rigid한 프로세스가 필요 없어졌고, 목표에 따라 동적으로 경로를 계획할 수 있게 되었습니다. 능력 경계와 일반화 성능이 동시에 향상되며, AGI가 닿을 수 있는 곳에 있는 것처럼 보였습니다.

하지만 문제도 곧 드러났습니다：

- **가짜 수요 범람**：MCP는 본질적으로 API의 형식 래퍼에 불과하며, 기존 API 장면에서 개발 비용이 극도로 낮아, "사용자보다 개발자가 많다"는 황당한 상황을 초래했습니다
- **AGI 환각**：커뮤니티는 "충분한 MCP를 연결하면 AGI를 달성할 수 있다"는 망상에 빠졌고, 모델 자체의 능력 한계를 무시했습니다
- **Context 오염**：도구 declaration의 평면적 남용이 컨텍스트 재난을 초래했고, 수백 개의 도구 정의가 창을 점유하며 모델의 Instruction Following 능력을 심각하게 훼손했습니다. 이 문제를 완화하기 위해 주류 Agent 프레임워크는 도구 수를 제한하기 시작했습니다——Cursor 에디터는 한때 상한을 80개로 설정했습니다

위기는 지혜를 낳습니다. 이 단계의 경험은 이후의 설계 철학을 깊이 있게 바꿨습니다：

- 통일된 규격은 커뮤니티의 거대한 힘을 이끌어낼 수 있습니다——표준화는 생태계 번영의 초석입니다
- Context 관리는 정교해져야 합니다——"hide tool result" 등의 단순한 전략의 등장은, 더 체계적인 Context 퇴출 메커니즘을 예고했습니다

## 제4장：Skills의 부상——Context 관리의 차원 상승 전쟁

MCP의 평면적 노출이 한계에 다다를 때, Skills가 탄생했습니다. 이는 단순한 도구의 재편성이 아니라, Context 관리 전략의 차원 상승입니다.

Skills가 더 나은 이유는 무엇일까요? 그것은 세 가지 돌파를 실현했습니다：

- **계층화된 노출**：평평한 도구 목록을 트리 구조로 조직화하고, 필요에 따라 펼쳐 볼 수 있게 하여, Context 오염을 피하면서도 소중한 컨텍스트 창 공간을 절약합니다
- **능동적 Context**：모델이 정보를 수동적으로 받아들이는 것이 아니라, 언제, 어느 층의 Context를 획득할지 자율적으로 결정합니다
- **SOP 수준의 지시**："무엇을 할 수 있는가"(MCP의 "나는 XX 도구가 있습니다")뿐만 아니라, "어떻게 하는가"——상세한 표준 작업 절차가 내장되어 있어, 도구에 지능형 패치를 적용하는 것과 같습니다

더욱 파괴적인 것은, 많은 Skills가 완전히 자연어로 정의되어 프로그래밍이 필요 없다는 점입니다. 이는 커뮤니티 참여의 문턱을 크게 낮추어, 프로그래머가 아닌 비즈니스 전문가도 생태계에 Context 자산을 기여할 수 있게 했습니다. 어떤 의미에서 이는 제2단계 Agent Workflow의 부활과 초월입니다——자연어의 유연성을 사용하여 워크플로우의 구조적 장점을 되살린 것입니다.

하지만 이는 동시에 모델에게 새로운 도전을 제기합니다：

- **능동적 컨텍스트 제어 능력**：수십 번의 도구 호출 후에도, 처음 안낸 특정 Skill의 존재를 기억할 수 있는가?
- **장문맥 기억 능력**：깊은 호출 체인 속에서 상위 Context에 대한 인식을 어떻게 유지할 것인가?

경험은 이미 명확합니다：

- Context는 계층화되어야 하며, 능동적으로 노출되어야 합니다
- 커뮤니티가 공동 구축하는 것은 도구뿐만 아니라, 프로세스 지식——SOP, 모범 사례, 도메인 방법론입니다

## 진행 중인 트렌드：Context 관리의 정교화된 진화

위의 진화사에서, 우리는 세 가지 연속적인 주선을 명확히 볼 수 있습니다：

### 1. 평면에서 계층으로：확장성의 승리

수동적으로 모든 Context를 획득하는 시대는 끝나가고 있습니다. 더 정교하고, 더 경제적이며, 확장성이 더 강한 계층화된 노출이 주류가 되고 있습니다. 이는 엔지니어링 최적화일 뿐만 아니라, 인지 패러다임의 전환입니다——Context의 획득은 정보의 폭격이 아닌, 정보의 채집이어야 합니다.

### 2. 모델 자율성의 지속적인 향상

Bitter Lesson(쓴 교훈)은 여기서도 지속적으로 힘을 발휘하고 있습니다：기반 모델의 지능이 향상되고, Instruction Following 능력이 지속적으로 돌파하면서, 개발자는 더 복잡한 구조를 정의할 수 있고, 모델은 이를 이해하고 실행할 수 있습니다. Agent Workflow는 "less structure"가 되어가고 있습니다——코드 정의가 필요한 rigid한 프로세스에서, 자연어로 기술되는 유연한 Skills로 진화하고 있습니다. 구조가 적을수록, 지능은 많아집니다.

### 3. 커뮤니티 참여 장벽의 지속적인 감소

생태계의 폭이 지능의 높이를 결정합니다. Context 기여에 프로그래밍 능력이 더 이상 필요하지 않고, 비즈니스 전문가가 자연어로 직접 Skills를 정의할 수 있게 되면, 커뮤니티의 창의성은 완전히 항방됩니다. 이러한 민주화 과정은 기반 모델의 능력 경계를 빠르게 확장하고 있습니다.

## 다음 장：사전 정의에서 장면 고유로

하지만 이야기는 끝나지 않았습니다. 새로운 트렌드가 싹트고 있으며, Context의 공급 방식을 변화시킬 것입니다.

### 트렌드 1：「사전 정의」에서 「장면 제공」으로

과거의 Context는 모두 사전 정의되었습니다：개발자가 MCP 서버를 작성하고, Skills를 패키징하며, 사용자가 수동으로 선택하여 로드합니다. 미래의 Context는 장면이 능동적으로 제공할 것입니다.

세상을 상상해 보세요：커피숍 운영자는 App이나 미니프로그램을 개발할 필요 없이, "Context 인터페이스"를 구현하기만 하면 됩니다——사용자의 Agent가 지오펜스에 진입하거나 매장 내 QR 코드를 스캔하면, 해당 장면의 Context 패키지를 자동으로 수신합니다. 이 Context에는 다음이 포함됩니다：

- 메뉴와 추천(인간을 위한 GUI가 아닌, Agent를 위한 구조화된 데이터)
- 주문 프로토콜(Skill과 유사한 자연어 SOP)
- 결제 프로세스
- 대기 시간 모델

인간을 위한 GUI를 만드는 것에서, Agent를 위한 Context 프로토콜을 만드는 것으로——이는 디지털 월드의 상호작용 패러다임의 근본적인 전환입니다.

### 트렌드 2：「들어가기만 하고 나오지 않음」에서 「유연한 퇴출」로

현재의 Context 관리는 기본적으로 일방향입니다：로드, 로드, 다시 로드——창이 폭발할 때까지. 미래에 필요한 것은 Python의 `with` 문과 같은 컨텍스트 매니저 같은 것입니다：진입도 정의하고, 퇴출도 정의합니다.

사용자가 커피숍 장면을 떠나면, Agent는 자동으로 다음을 수행해야 합니다：

- 상세한 상호작용 로그를 아카이브합니다("라테 한 잔 주문하고, 캐러멜을 바닐라로 변경하고, 얼음 적게")
- 활성 Context에서 해당 장면의 MCP/Skills를 제거합니다
- 농축된 요약만 보존합니다("Blue Bottle Coffee에서 35원 소비")

이러한 Context 퇴출 메커니즘은 장기적인 오염을 피하면서도 정확한 기억을 실현할 수 있으므로, 장기적으로 실행되는 Agent 시스템에 필수적인 능력입니다.

## 한 잔의 커피로 미래를 보다

간단한 예로 구세계와 신세계를 연결해 보겠습니다：

**구 패러다임**：

커피숍에 들어간다 → QR 코드를 스캔한다 → 미니프로그램/H5 페이지로 이동한다 → 사용자가 수동으로 주문하고 결제한다

**신 패러다임**：

커피숍에 들어간다 → Agent가 장면 Context를 자동으로 감지한다 → 능동적으로 사용자에게 알린다："Blue Bottle Coffee의 메뉴를 감지했습니다. 소개해 드릴까요?" → 사용자가 자연어로："얼음 적게 아메리칸노, 원두는 에티오피아" → Agent가 선택, 커스터마이징, 주문, 결제를 자율적으로 완료한다 → 대기 시간을 예측하고 리마인더를 설정한다 → 퇴점 후 Context를 자동으로 정리하고, 소비 기록만 보존한다

사용자는 순수한 의도 표현으로 회귀하고, 모든 중간 프로세스는 장면화된 Context의 지도 아래 Agent가 자율적으로 완료합니다.

## 결론：Context 네이티브한 지능형 생태계를 향하여

주문에서 워크플로우로, MCP에서 Skills로, 그리고 장면 고유의 Context로——우리는 명확한 주선을 보고 있습니다：Context는 인간의 입력의 부속물에서, 생태계의 공생 인프라로 진화하고 있습니다.

AGI의 비밀은 어떤 클로즈드소스 모델의 매개변수 수에 있는 것이 아니라, 커뮤니티가 맥락이 풍부하고, 역동적이며, 장면화된 디지털 월드를 구축할 수 있는가에 있습니다. 모든 커피숍, 모든 도서관, 모든 실험실이 AI에 네이티브한 Context를 제공할 때, 지능은 비로소 "창발"합니다.

이는 기술의 진화일 뿐만 아니라, 협력 패러다임의 혁명이기도 합니다. 사용자보다 많은 개발자에서, 개발자보다 많은 장면 참여자로, 생태계의 다음 장은 모든 디지털 공간의 유지보수자에 의해 공동으로 집필됩니다.

**Context는 더 이상 모델이 처리해야 할 문제가 아니라, 세계가 지능에 제공하는 답입니다.**
